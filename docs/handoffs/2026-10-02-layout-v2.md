# Handoff: Timeline layout v2

**Status (2026-10-02):** design in progress, no code yet. Scope is agreed; several design
questions are still open (listed below). Next step: finish the open questions with the
owner, propose approaches, write a spec in `docs/superpowers/specs/`, get it reviewed,
then plan and implement.

Read first: [ARCHITECTURE.md](../ARCHITECTURE.md) (rendering contract, engine, gestures).

## What layout v2 is

One body of work, because every part depends on the same placement logic:

1. Vertical orientation, selectable in Settings, with a time-direction setting.
2. Gestures in both orientations, including momentum (flick and glide).
3. Fixing label overlap and visual clutter.
4. The Agenda (the list under the timeline) as a bottom dock or a slide-out drawer.
5. The cursor drawn as an arrow instead of a "Cursor" chip.
6. Optional snapping of the cursor to ticks.

## Decisions made (owner's words in quotes)

### Orientation and direction
- "Vertical layout for mobile, ensure gestures and momentum work. Vertical layout should
  be option for desktop tho too. Via settings."
- Assumed, not explicitly confirmed: the setting is **Auto / Horizontal / Vertical**,
  with Auto choosing vertical on narrow or portrait screens.
- Time direction in vertical: **future goes down** by default ("like reading a book"),
  with "maybe let's make that a setting" to flip it. Treat the flip as in scope.

### Scrolling and dragging (option A, plus the owner's amendment)
- **Drag with one finger or one mouse button moves through time (the cursor) in both
  orientations.**
- Vertical: wheel / two-finger scroll moves through time like reading a page;
  Ctrl+wheel or pinch zooms.
- Horizontal: vertical wheel zooms (as today); a sideways two-finger swipe moves through time.
- Momentum: a flicked touch drag keeps gliding. Whether mouse drags also glide is open.

### Clutter fixes (owner approved 1–6 "as revised"; 7 rejected)
1. **One compact chip per instant**, e.g. "Take Meds 6:00p". Seconds only when zoomed in,
   or on Now, the Cursor and the selected instant.
2. **Overlap layout**: place chips by priority (Now > Cursor > focused > selected >
   alarms > favorites > rest). An overlapping chip moves to another row with a thin
   connector to its marker; if there's still no room, nearby instants collapse into a
   "+3" chip that zooms in when tapped. Same logic in vertical (rows become columns).
3. **Live markers above the axis, saved instants below.** The owner suggested "now should
   always be above the line". The Cursor's readout takes over the two top lanes
   ("−6:41 from Now · +2:37 from Snooze 2"); its lock and save-span buttons appear when tapped.
4. **Short span chips**: show only the duration ("15:38"); endpoint names on tap or in
   the Agenda. Chips stay on screen (clamped, truncated with an ellipsis).
5. **Quieter defaults**: favorites and alarms show elapsed time or a countdown on their
   chip ("Rice · 20m ago", "Tea · in 6m") instead of a permanent lane; the lane appears
   when selected or switched on. Selecting shows only Selected→Now;
   Secondary→Selected becomes opt-in.
6. **Snoozes stay on the timeline** (they're history) but get a short name
   ("Test Alarm ⟲2" instead of "Snooze 2: Test Alarm") and are grouped with their
   original by the overlap layout.
7. ~~Fade past items~~. **Rejected. Never fade, dim or hide the past.** "Half the reason
   for this app is the historicals."

### Cursor as an arrow
- "Instead of 'cursor' … a sleek arrow icon pointing down. With the arrow edges curved inward."
- Proposed details: glowing cyan arrowhead, tip touching the axis where it points (in
  vertical it points at the axis from the side); time and offset readout beside it;
  double-tap the arrow saves an instant there (replacing the double-click on "Cursor");
  a single tap shows its tools (lock, save span, type a time).

### Agenda
- Name accepted ("Agenda"; code is still `ListPanel`, rename it).
- "Should either be dockable to bottom or a side slide out bar thing like hamburger menu
  slides out from left." The bottom dock stays the default ("looks ok in its default
  docked position below").

### Snap to ticks
- "Snapping cursor to timeline ticks (option enable)". A setting, off by default.

## Open questions (ask one at a time, in roughly this order)

1. **Vertical geometry**: where the axis sits (e.g. a left-hand column), which side
   chips and span lanes go on, where Now and Cursor live, and where the Agenda goes in
   vertical (drawer by default on phones?). This is visual: the brainstorming "visual
   companion" (mockups in a browser tab) was offered and not yet answered.
2. **Auto rule**: portrait aspect ratio, or a width threshold?
3. **Momentum details**: mouse fling too? Does snapping (to Now, instants, or ticks) happen
   at the end of the glide? Should a tap stop a glide?
4. **Snap to ticks**: which tick tier, and does it apply to ± steps?
5. **Overlap layout limits**: maximum rows before clustering; what a cluster chip shows.
6. **Dock vs drawer**: chosen in Settings, or by a toggle button in the Agenda header?
7. **Seconds threshold** for compact chips.

## Implementation notes (for whoever builds it)

- **Orientation abstraction.** The engine's `Frame` speaks in `x`/`screenW`. Generalize to
  a main-axis position (`pos(t)`, `mainSize`) plus orientation and direction. Rename
  `usePositionX` → `usePositionMain` (translate3d on X or Y). Row offsets
  (`--tl-label`, `--tl-time`, …) become cross-axis offsets; drive them from an
  orientation class or attribute on `.timeline`.
- **Direction flip** is a sign in the projection: `pos = mainSize/2 ± (t − center) · pxPerMs`.
- **Gestures** (`hooks/usePanZoom.ts`): currently reads `clientX` only. Use the main
  axis for the drag delta and threshold; map wheel axes per orientation (see decisions).
  Keep the existing touch rules (8px tap slack, 20px snap, a click guard that lasts one
  event) and their tests.
- **Momentum**: track pointer velocity over the last ~100ms; on release hand a velocity
  to the engine, which already schedules frames on demand. Add a "glide" state with
  exponential decay, cancelled by the next pointerdown, then call `endPan`/`settleCursor`.
- **Overlap layout**: put it in a pure `domain/labelLayout.ts` (items with position,
  width and priority → rows/columns and clusters) with unit tests. Recompute only when
  the result changes (`useFrameValue`), never per frame in React. Chip widths: measure once
  per label text and cache them.
- **Performance budget**: idle stays ~0% main thread. Nothing per-frame in React state.
  Re-run the pan/zoom benchmark (see the next-steps handoff) after the change.
- **Agenda drawer**: same component in two containers; the drawer is portaled, slides
  in from the left, and a menu button opens it.

## Constraints to respect
- History is core: no fading, dimming or hiding past items.
- Core flow (cooking): one tap captures an instant; label it later; "+13 from it" with an
  alarm; look back at elapsed time. Fewer taps wins.
- Everything glows, through theme tokens.
- Don't add unrequested interaction changes; propose them first.
